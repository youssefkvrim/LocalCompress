- Keep file processing fully local: no token must be forwarded to workers.

P1 - Edge integration
- Put OIDC/OAuth2 at route/ingress level (reverse-proxy auth), not in the browser app.
- Preserve static hosting behavior and all security headers (COOP/COEP/CSP).

P2 - Session UX
- Add a readonly "authenticated" banner from response header/cookie presence.
- Keep application functional offline once the static files are cached.

P2 - Security checks
- Verify no auth header/cookie is readable by workers.
- Verify blocked egress remains blocked with SSO enabled.

P3 - Ops
- Add runbook: token expiration behavior, logout path, incident fallback.

Put Safran SSO in front of the LocalKit site, so only authenticated
Safran users can load the application.

Notes for whoever implements it:
- SSO protects the delivery of the application only. The compression
  itself never contacts any server, so no file or file name is involved.
- Do it at the web server / reverse proxy level (e.g. the intranet SSO
  gateway in front of nginx or IIS). The application code needs no change.
- Keep the security headers from deploy/ (CSP, COOP, COEP, etc.) on every
  response, including after the SSO redirect, or the app refuses to run.
- The SSO domain must not be added to the CSP: the app itself must never
  talk to it.
- Check that offline use still works after the first authenticated load
  (the service worker serves the cached application).
